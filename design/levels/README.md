## 怎么改关卡

关卡不再手摆。每座塔是一个 Python 描述文件,生成器把它变成 Godot 场景:

```bash
python3 tools/level_builder/build.py            # 全部
python3 tools/level_builder/build.py tower_2    # 只建一座
```

| 文件 | 作用 |
|---|---|
| `tools/level_builder/levels/tower_N.py` | **改这里**:用 16px 的格子写地形、暗区、守卫、柜子、通风管、门禁、探照灯 |
| `tools/level_builder/level_dsl.py` | 描述语言 + 路线搜索 + 检查(Ryn 的能力写在这里) |
| `tools/level_builder/build.py` | 生成场景;剧情台词、下一关、背景氛围从原场景原样保留 |
| `src/levels/tower_*.tscn` | 生成结果,**不要手改** |
| `design/levels/tower_N.txt` / `.png` | 字符地图 / 预览图(地形 + 暗区 + 巡逻 + 验证路线) |

## 每次生成都会检查

1. **路线可达**:按 Ryn 的真实能力(站 42px、蹲 34px;跳 3 格高、跑跳 4 格宽;蹲着钻 40px 的缝;
   爬梯;通风管;拆盖板和栅栏)在格子上搜一条出生点到出口的路;有通风管的塔再搜一条**不走通风管**的。
2. **守卫不会挡死路**(用户说的「巡逻卡住」):把一个守卫的巡逻段拿掉,如果出生点因此到不了出口,
   这段就是必经之路 —— 必经之路上的守卫,巡逻范围里必须有暗区或柜子可以躲。
3. 守卫巡逻线脚下都有地、净空够 48px、不经过梯子口(会掉下去);柜子、存档点、通风管口都站得住。

然后用真实物理走一遍:

```bash
godot --path . --headless --quit-after 200000 res://src/levels/tower_2_refinery.tscn -- --demo=route
godot ... -- --demo=route --route-node=DevRouteNoVent     # 不走通风管的那条
```

机器人沿着生成器写进场景的路线(`DevRoute`)一步步走,每一步超时就报出是哪一步、卡在哪。

**全流程体检**(2026-10-13):加 `--pace`,机器人边走边记存档点和「关口」(被守卫巡逻范围 / 灯盯得到的路段,
`src/dev/pace_probe.gd`)。一次跑完 `LevelSequence` 里所有有路线的关卡,出报告和时间线图:

```bash
python3 tools/pacing/run_pacing.py            # → production/qa/pacing-<日期>.md / .png / .json
python3 tools/pacing/run_pacing.py --reuse    # 不重跑,只重出报告
```

报告会列出「照主路线走碰不到的存档点」(感应框只有 28px 宽,放在梯子口、落点旁边一两格就会被跳过)。
生成器也会查:存档点离路线超过 1 格算「问题」(`level_dsl.checkpoint_route_issues`)—— **存档点放在
「从梯子 / 落点下来以后往前走」的那一段上**,不要放在落点身后。
2026-10-11:四座塔六条路线 + 下行关一条,全部 `REACHABLE`。

| 写法 | 作用 |

| `lv.window(x0, y0, x1, y1, kind="window"/"breach")` | 墙上的窗(石框铁栏)/ 塌了的破口,透过去看到夜景;只是背景 |

| `lv.warm_window(x, row)` | 旧屋外墙上的暖窗(只给旧屋) |

| sense | 造型 | 发现方式 | 关卡里的规矩(生成器检查) |
